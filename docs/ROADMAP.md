# 路线图

第一版（MVP）目标已经完成：本机发现 → 索引 → 浏览 → 搜索 → Git 多机同步 → 归档。
以下按优先级列出后续方向。

## 近期（体验与稳健性）

1. **搜索体验**
   - 中文分词（可选的自定义 tokenizer 或 jieba 词表）；
   - 搜索结果里「上下文前后各 N 条消息」直接展开；
   - 搜索历史与常用筛选条件的记忆。
2. **归档策略**
   - 按项目 / 数据源批量归档的界面（当前为「按天数」+ 单会话）；
   - 归档体积报告与压缩级别可选。
3. **索引维护**
   - 设置页提供「索引体检」：一致性检查、孤儿文件/会话清理、VACUUM；
   - 适配器升级后自动提示重建索引。
4. **错误与日志**
   - 应用内「诊断」页面：展示最近日志与错误分类计数；
   - 导出诊断包（自动脱敏，不含 prompt 正文）。

## 中期（能力扩展）

5. **Secret Scan（规格 §16 提到的扩展）**
   - 提交前扫描疑似密钥（正则 + 熵检测），在 UI 中提示并支持一键排除该会话的某条消息；
   - 仅提示，不修改原始文件。
6. **加密同步**
   - 使用 `age` 对快照做端到端加密后再提交，兼容现有 Git 流程。
7. **更多数据源**
   - 通过相同 Adapter 接口接入更多 AI Coding CLI（Claude Code、Gemini CLI 等）。
8. **会话对比**
   - 同一会话在不同机器上的版本差异查看（复用 Git diff）。
9. **大文件与流式渲染**
   - 超长工具输出的「按需分段加载」（当前是一次性加载单条消息文本）。

## 长期（可选）

10. **自建同步服务**：仍以 Git 为唯一同步机制，但提供仓库托管模板与 CI 校验（schema 版本、体积、敏感信息）。
11. **团队只读视图**：把仓库当数据源只读浏览（不涉及用户系统与在线聊天）。
12. **插件化 Adapter**：把 Adapter 抽象为可外部加载的模块。

## 明确不做

- LLM 长期记忆 / Embedding / 向量数据库 / RAG / AI 摘要；
- 云同步服务、用户系统、团队协作、在线聊天；
- 修改或「回写」Codex / Kimi Code 的原始会话文件；
- 把会话自动恢复到另一个 AI 工具的会话状态。
