# Local AI Chat Manager 前端视觉重构方案

> 状态：v2 已落地（组件级重设计，2026-09-16）  
> v1（本文档 §1–§11）完成了 token 与页面层级；v2 在其基础上把**每个组件当作物件重新设计**，见文末 §12。  
> 适用范围：`src/app`、`src/components`、`src/features`、`src/gallery` 与 `src/index.css`。

## 1. 结论先行

建议选择“表现层重构”，而不是继续做零散精修，也不建议推翻现有产品结构。

应当保留：

- `会话 / 搜索 / 同步 / 设置` 四个一级入口；
- 会话页“来源与项目 / 会话列表 / 会话正文”的三栏关系；
- 现有 Tauri、Zustand、IPC、虚拟列表、分页加载和数据模型；
- Local-first、原始文件只读、Git 同步不丢数据的产品原则。

应当重构：

- 颜色、字号、间距、圆角、边框、焦点和状态 token；
- 顶部工具栏的信息优先级；
- 会话列表与消息阅读器的视觉组件；
- 搜索筛选、同步状态和设置分组的呈现方式；
- 窄窗口、空状态、加载、错误、成功、危险操作和无障碍状态。

原因不是“现在的蓝色不好看”，而是当前所有页面都使用近似的灰色表面、1px 边框、10.5–12px 小字和相近权重，导致内容虽然齐全，却像一个调试面板：能用，但缺少层级、信任感和产品识别度。

## 2. 产品视觉定位

### 2.1 推荐方向：Quiet Archive Workbench（安静的本地档案工作台）

这个产品不是新的 AI 聊天工具，也不是营销型 SaaS。它更像：

- 一座只保存在本机的会话档案库；
- 一个可以追踪来源、设备和同步状态的工作台；
- 一个面向开发者、但不应只像 IDE 附属面板的桌面应用。

推荐的视觉关键词：

- **可信**：清楚表达只读、本地、同步目标和风险；
- **安静**：阅读内容时让工具界面退后；
- **精确**：路径、时间、设备、Git 状态使用稳定的排版规则；
- **有层次**：不同表面承担不同任务，而不是所有内容都靠边框分隔；
- **非 AI 套模板**：不用紫蓝渐变、发光球、玻璃卡片和聊天机器人插画。

### 2.2 产品专属视觉锚点

品牌识别不依赖装饰图形，而来自产品自身的数据：

- 来源：Codex / Kimi Code；
- 位置：本机 / 同步仓库 / 其他设备；
- 状态：只读 / 未同步 / 已同步 / 冲突 / 部分解析；
- 时间：扫描时间、更新时间、同步时间；
- 可追溯性：会话、消息序号、文件路径和机器标识。

这些信息应该形成一套一致的图标、状态色、徽标和元数据排版，而不是散落在各种低对比度小字中。

## 3. 当前设计诊断

本次独立评审的 Nielsen 启发式得分为 **22/40（可用，但需要显著改进）**。

### 3.1 值得保留的基础

1. 三栏结构符合桌面端高频浏览习惯，筛选、定位和阅读的空间关系正确。
2. 会话与消息已经使用虚拟滚动、分页加载和长内容折叠，工程基础支持大数据量。
3. 同步冲突明确说明“不自动合并、不丢弃数据”，这类可靠性表达应成为全产品的设计基调。

### 3.2 核心问题

#### P1：视觉层级过平

- `src/index.css` 只有少量中性表面色和一个蓝色强调色；
- `src/components/ui.tsx` 中按钮、徽标、标题栏和字段主要依赖同一组边框、圆角和小字号；
- 截图中左栏、列表和正文几乎处于同一个黑色平面，阅读器没有成为视觉主角。

结果：用户能看到很多信息，却不容易判断“现在最重要的是什么”。

#### P1：文字过小，元数据长期处于弱对比度

代码中大量使用 10.5px、11px、11.5px 和 12px 字号。小字号可以用于少量辅助信息，但当前路径、时间、设备、同步状态、消息角色和操作提示都被压在这个范围内。

结果：高密度不等于高效率；用户需要不断靠近、聚焦和重新扫描。

#### P1：顶部工具栏和搜索筛选区决策点过多

- 顶部同时出现产品名、统计、四个导航、扫描进度、来源警告、同步状态、搜索和扫描；
- 搜索页同时出现关键词、来源、项目、设备、起止日期、仅正文和排序。

结果：所有功能都“可见”，但主任务不够突出。

#### P1：窄窗口会丢失核心筛选能力

`ConversationsPage` 在 `lg` 以下直接隐藏来源/项目栏，中间列表仍固定为 340px，没有抽屉、返回或筛选摘要作为替代。

结果：窗口一窄，三栏 IA 不是自适应，而是少了一部分。

#### P1：状态与无障碍表达不完整

- 输入框使用 `outline-none`，焦点主要靠细边框颜色变化；
- 当前页和当前会话缺少 `aria-current` / `aria-selected`；
- 扫描、同步、错误和成功缺少统一的 live status；
- 选中状态、角色和风险有时主要靠颜色表达。

#### P2：同步与设置页面像技术信息堆栈

同步页把仓库、变更、文件、步骤、归档、数据源和日志放在同一长页；设置页把普通扫描与“重建索引”并排。技术信息完整，但缺少“当前状态 → 推荐动作 → 高级诊断”的顺序。

## 4. 新设计系统

### 4.1 表面层级

建立四层表面，不再让所有页面共用一个背景：

1. `canvas`：应用最底层背景；
2. `panel`：来源栏和会话列表；
3. `reading`：会话正文与主要工作区；
4. `overlay`：菜单、弹层、确认框和浮动反馈。

深色主题使用石墨灰而非纯黑；浅色主题使用略带冷暖倾向的中性色而非纯白。表面之间优先用背景差异和间距分组，边框只用于真实边界。

### 4.2 字体层级

建议限制为以下常用层级：

- 页面标题：16px / 600；
- 面板标题：14px / 600；
- 正文与控件：13.5–14px / 400–500；
- 元数据：12px / 400；
- 极少量技术标识：11px mono。

规则：核心路径、同步状态和错误原因不能长期使用最低字号或最低对比度。

### 4.3 颜色角色

颜色按语义命名，不按具体色值命名：

- `accent`：当前选择、主要动作、焦点；
- `success`：已完成、已同步；
- `warning`：未配置、部分解析、需要注意；
- `danger`：冲突、破坏性操作、阻塞错误；
- `info`：扫描、索引、普通进度；
- `source-codex` / `source-kimi`：仅用于来源识别，不承担成功或失败含义。

每一种语义状态同时使用图标或文字，不依赖颜色单独传递信息。

### 4.4 圆角、边框与阴影

- 控件圆角：6px；
- 面板/卡片圆角：8–10px；
- 弹层圆角：10–12px；
- 常规面板不使用阴影；
- 浮层才使用阴影；
- 列表行以背景和间距区分，减少连续横向边框。

### 4.5 焦点与动效

- 所有交互控件统一 `focus-visible` ring；
- hover 只做轻微表面变化，不移动布局；
- 页面切换不使用大幅过渡；
- 扫描、同步等状态允许轻量动效，但必须支持 `prefers-reduced-motion`；
- 成功反馈应短暂但可感知，失败反馈应持续到用户处理或关闭。

## 5. 全局框架改造

### 5.1 顶部工具栏

保留顶部工具栏，但按三个区域重组：

- 左：产品名 + 当前资料库摘要；
- 中：四个一级导航，使用清晰的 segmented navigation；
- 右：全局搜索入口、同步状态、更多菜单。

“扫描”不应永久抢占主按钮。首次未索引时，它是主动作；正常使用后，它退为工具动作，扫描进度通过统一状态区域展示。

### 5.2 三栏工作区

推荐尺寸：

- 来源/项目栏：220–240px，可折叠；
- 会话列表：340–380px，可在合理范围内调整；
- 正文：剩余空间，内部阅读宽度建议限制在 880–960px。

宽度不足时：

- 来源栏进入抽屉，工具栏保留“筛选”入口和当前筛选摘要；
- 再窄时变为“会话列表 → 会话详情”两级视图；
- 任何断点都不能让筛选功能直接消失。

## 6. 页面级方案

### 6.1 会话页

#### 来源/项目栏

- 用分组标题、计数和选中状态建立层级；
- Codex/Kimi 来源使用克制的专属标识；
- 项目路径提供 tooltip 或复制能力；
- 顶部增加“全部会话”，底部放置数据源健康状态；
- 空状态直接提供“扫描”和“打开设置”动作。

#### 会话列表

- 会话标题提升到 13.5–14px；
- 每行只保留两层信息：标题；来源/项目/更新时间；
- 消息数、设备和同步状态压缩为次级 metadata 或状态图标；
- 选中行使用明确背景、焦点 ring 和状态文字，不只用蓝点；
- 日期分组标题使用 sticky header，但降低装饰感。

#### 会话阅读器

- 让 assistant 正文成为阅读主轴，user 内容用轻微表面差异区分；
- 工具调用/结果使用 console-like block，与普通正文明确分层；
- 路径、时间、消息数和同步状态不要全部挤在标题后的一行；
- 长内容避免消息块与页面形成双重滚动；
- 保留“显示/隐藏工具消息”，视觉重构第一阶段不改变默认行为；是否默认折叠工具消息作为后续独立产品决策。

### 6.2 搜索页

默认首层只展示：

- 大尺寸关键词输入；
- 搜索按钮；
- 排序；
- 已启用筛选的 chips。

来源、项目、设备、日期和“仅正文”放入高级筛选区，仍然完整保留现有功能。增加：

- 一键清除筛选；
- 起止日期校验；
- 归档会话是否参与搜索的明确说明；
- 搜索结果返回后保留查询与筛选状态。

“点击结果定位到具体消息”是核心体验缺口，但涉及状态和加载逻辑，建议单列为功能增强任务，不与纯视觉改造混在同一个提交中。

### 6.3 同步页

按风险和任务顺序重组：

1. 当前仓库和同步健康状态；
2. 推荐的下一步操作；
3. 待同步内容摘要；
4. 同步结果；
5. 归档、日志和高级诊断。

`立即同步` 前明确展示目标仓库、远端、待同步会话/文件数量和隐私提醒。冲突状态保留现有“不自动合并、不丢数据”的文案，并把它提升为产品的可靠性样板。

### 6.4 设置页

保留现有字段，但重组为：

- 数据源；
- 同步与隐私；
- 扫描与归档；
- 外观与行为；
- 诊断信息；
- Danger Zone。

页面主体使用受控最大宽度，避免宽屏上两张技术表单卡片无限拉开。“重建索引”进入 Danger Zone，增加影响说明和确认。显示未保存状态，离开页面前保护草稿。

## 7. 组件与代码落点

### `src/index.css`

- 建立完整的 surface / text / border / semantic / focus token；
- 建立 11/12/14/16px 类型层级与行高；
- 增加统一 focus ring、selection、scrollbar 和 reduced-motion 规则；
- 分别调校浅色与深色主题，禁止机械反色。

### `src/components/ui.tsx`

建议拆分或扩展：

- `Button`：primary / secondary / ghost / danger，包含 hover、active、focus、disabled、loading；
- `IconButton`：必须有可访问名称；
- `StatusPill`：统一扫描、同步、冲突和来源状态；
- `PanelHeader`：支持分层标题、metadata 与操作槽；
- `FormField`：真正绑定 label、hint、error 和 control；
- `SectionCard`：只用于设置/同步的语义分组；
- `EmptyState`：支持主动作与次动作；
- `Notice`：info / success / warning / danger；
- `Skeleton` 或稳定的 loading placeholder。

### 页面组件

- `src/app/App.tsx`：重组顶部工具栏与统一状态区；
- `ConversationsPage.tsx`：响应式三栏与抽屉替代；
- `SourceSidebar.tsx`：来源/项目层级；
- `SessionList.tsx`：会话行和 sticky 分组；
- `ConversationViewer.tsx`：阅读排版与消息类型；
- `SearchPage.tsx`：主搜索 + 高级筛选；
- `SyncPage.tsx`：状态、预览、执行、结果、诊断；
- `SettingsPage.tsx`：表单语义、分组与 Danger Zone。

## 8. 分阶段实施

### Phase 0：基线与验收样本

- 固定演示数据；
- 为四个页面各保留浅色/深色、普通/空/错误状态截图；
- 记录 1440×900、1180×800、900×700 三个窗口尺寸；
- 当前 README 截图与源码已经有差异，重构完成后统一更新。

验收：所有后续改动都能与同一份数据和同一组窗口尺寸比较。

### Phase 1：设计基础层

- 重写 token、类型层级、焦点、控件状态；
- 重构基础 UI 原语；
- 暂不调整页面业务逻辑。

验收：四页视觉一致；键盘焦点清楚；正文不再依赖 10.5–12px；浅色/深色均达到 WCAG AA 级别的常规文本对比目标。

### Phase 2：会话工作区

- 重构顶部工具栏、来源栏、会话行和消息块；
- 完成窄窗口抽屉/两级视图；
- 完成会话页空、加载、部分解析和错误状态。

验收：用户 5 秒内能识别当前来源、当前会话和正文；900px 宽度仍能访问全部筛选；长标题和长路径不破坏布局。

### Phase 3：搜索、同步与设置

- 搜索主次层级与高级筛选；
- 同步状态、预览和结果层级；
- 设置分组、未保存状态和 Danger Zone。

验收：搜索首屏不再同时出现 8 个同权重决策点；同步前能确认目标和待同步内容；危险操作不再与普通操作同权。

### Phase 4：恢复力与视觉 QA

- 检查 hover、active、focus、disabled、loading、empty、success、warning、error；
- 检查键盘流程、200% 缩放、长中文/英文/路径、空数据和大量数据；
- 运行构建、静态检测和桌面端截图对比；
- 更新 README 示例图。

验收：无关键控件仅靠颜色表达；无不可见焦点；无窄窗口功能消失；无双重滚动造成的主要阅读阻塞。

## 9. 不建议做的事情

- 不通过增加渐变、发光、玻璃或大面积阴影来“显得高级”；
- 不为了现代感把所有内容改成卡片；
- 不在同一轮同时重写 IPC、状态管理和视觉组件；
- 不先做动效，再补层级与无障碍；
- 不把所有技术信息隐藏掉，开发者仍需要路径、设备和 Git 状态；
- 不把搜索定位、默认折叠工具消息等功能行为偷偷混进纯视觉提交。

## 10. 推荐提交拆分

1. `refactor(ui): establish visual tokens and primitives`
2. `refactor(ui): redesign conversation workspace`
3. `refactor(ui): clarify search sync and settings surfaces`
4. `fix(ui): harden responsive and accessibility states`

每个提交都应可单独构建、可截图验证、可回退。若希望减少提交数量，可将 1+2 合并、3+4 合并，但不建议把全部重构压成一个难以审查的大提交。

## 11. 最终决策

采用“保留结构的视觉重构”：

- 不重新发明产品；
- 不破坏现有高性能工程基础；
- 用新的设计系统和页面层级，把现有功能从“调试工具”提升为“可信的本地会话档案工作台”。

这条路线能解决当前大部分“丑”的根因，同时把功能风险控制在表现层范围内。

## 12. v2：组件级重设计（2026-09-16 落地）

v1 换的是「皮」（token/色板/层级），组件本身的造型没有被设计过：原生 `<select>` 直接出镜、
按钮是描边圆角矩形、看得最多的会话行和消息块最平庸。v2 改为**组件设计先行**：

**机制**：`?gallery` 组件画廊（`src/gallery/Gallery.tsx`）陈列每个组件的全部状态与深浅主题，
`tools/gallery_shot.mjs` 逐区块截图。组件在画廊过关后才进页面。

**材料**：
- 字体本地打包：拉丁 Geist / 等宽 Geist Mono（变量字重，woff2 进产物，Tauri 离线可用），
  CJK 回落系统栈；类型层级改为「字号 × 字重 × 字距」三者分层；
- 控件皮肤统一为 `.field`：内陷表面 + inset ring（比 border 锐利、不撑布局）+ 顶内阴影，
  hover/focus/invalid 只改 ring 颜色；
- 圆角收敛为三档：控件 6 / 面板 8 / 浮层 12。

**组件结论**：
- `Select` 自绘（触发器 + 浮层 + 选中对勾 + 完整键盘导航），原生 select/date/checkbox 不再出镜；
- `Toggle` 为真正的拨杆开关（`role="switch"`）；
- `Button` 四语气：primary 渐变浮起、secondary inset ring + 轻投影、danger 实体淡染；
- `SessionRow` 是圆角物件（容器内缩、选中 = 填充 + inset 强调条、徽标微型化），列表不再有连续 hairline；
- 工具调用/结果是带头栏的终端块（工具名 + 折叠 chevron + hover 复制），默认仍展开；
- `StatusPill`/`Notice` 无边框淡染，图标承担色觉冗余；
- 新增 `SidebarRow`/`SectionLabel`/`ListRow`/`Chip`/`DirectoryInput`/`Drawer`，页面里的手写重复模式收敛进 `ui/`。
