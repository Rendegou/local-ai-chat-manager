## 1. 一句话结论

给每个工具写 Rust 适配器追不上生态，所以这次不是「再加几个数据源」，而是**给了一个不需要写代码的入口**：
用户指一个目录、填一份字段映射，任何工具的 JSONL / JSON 历史都能变成常驻来源，带「试解析」在保存前验证。
同时把「我们还没适配的工具」显式列进「添加来源」，让「产品不支持」变成「还没做」。

## 2. 你提的两个问题，分别怎么解的

### 2.1 「数据源可以再加吗？这样无法满足所有人」

你的判断是对的，而且瓶颈不在清单长度——**在结构**：`registry.rs` 里 `const CATALOG` 是编译期常量，
加一个原生来源 = 写一个 Rust parser + 改 catalog + 加 watch extensions。用户自己不可能加，
而新工具出现的速度远快于写 adapter 的速度。

这次做了三件事：

**① 加了一批零 Rust 成本的「已识别 · 待适配」条目**（Cline、Continue.dev、Aider）。
`access: "pending"`：我们认识这个工具、描述里写了常见位置，但还没写适配器。它们出现在「添加来源」里，
而不是在列表里找不到、让人以为永远不会有。每个 pending 行还带一个「用自定义来源接入」按钮——
把「我们还没做」直接接上「那我自己接」。

> 只放了 3 个，且描述里的路径**明确标注「未在本机验证」**。你这台机器 7 个内置来源都有真实数据，
> 外部工具的路径我无从核实；写成一个看起来权威的默认路径更糟——一旦写错，用户会照着去指一个空目录。

**② 导入自动识别**：原来只认我们自己的模板（`{schemaVersion:1,...}` 或 Markdown），
现在按「严格 → 宽松」逐个探测器尝试——标准包 / `{messages:[...]}` / 顶层数组 / JSONL 转录 /
Claude Code 转录 / Markdown。识别总是猜测，所以**预览里会写清猜的是什么**（「识别为：JSONL 转录」），
用户有权在确认前知道依据。

**③ 用户自定义来源（真正的答案）**：`GenericJsonAdapter` + 一份可配置的 `FieldMapping`
（布局 / 消息数组路径 / 角色·正文·时间·工具·标题·项目字段 / 角色映射 / 扩展名 / 深度），
配一个「试解析」按钮。**不需要为任何新工具写代码。** 详见 `docs/ADAPTERS.md` 的对应一节。

### 2.2 「中英文切换这个功能去哪里了」

位置没变：**设置 → 外观与行为 → 语言**。但这是我的失误，而且是两个问题叠在一起：

1. **发现成本**：上一轮我把设置页从「一条长页」改成分区导航，默认停在「数据源」，
   语言和主题被挪到第 4 个分区。以前往下滚就能看见，现在要先猜到它在哪个分区。
   我在上一轮的报告里只写了「分区导航」，没提这件事对既有功能的影响。
2. **更根本的矛盾**：语言和主题在选择时**立即生效**（`patchSettingsDraft` 把 theme/language
   写进 store 做预览），却又被算进「未保存的修改」。于是实际行为是：改语言 → 界面立刻变英文 →
   一离开设置页就被拦下问「要保存吗」→ 点「放弃修改」，语言**翻回中文**。
   即时生效的偏好被塞进「草稿 + 显式保存」的模型里。

这次的修法：

- 新增 `setAppearance({theme?, language?})`：外观字段**立即落盘**，草稿里的其它字段原样保留
  （不会顺手提交用户没想保存的改动），并据 draft/saved 重算「未保存」标记；
- 标题栏「更多操作」里加两组内联选项（界面语言 / 主题），随时可达；
- 设置页保留完整选择（含「跟随系统」），并在分区里写明「即时生效，不需要点保存」。

结果：改语言 → 立刻生效且立刻保存 → 离开设置页**不会**被拦下，也没有「放弃修改会翻回去」的惊吓。

## 3. 顺带修掉的一个既有缺陷

`cargo test -p aichat-core` 原来稳定失败 7 项，**与任何改动无关**：这些集成测试的 fixture
只把 codex/kimi/cursor/zcode 钉到临时空目录，而 WIP 新增的 claude / gemini / workbuddy 适配器
在「设置里没有路径」时会回退到真实用户目录，于是 `library.scan()` 把开发机上的真实会话也扫了进来
（`assert_eq!(parsed, 2)` 实际得到 126）。**在任何装了 Claude Code 的机器上都会失败**——测的是环境而不是代码。

新增 `tests/common/mod.rs` 的 `isolate_sources(settings, tmp, keep)`：

- `keep` 之外的来源一律 `enabled: false`——`Library::adapters()` 会在构造前就过滤掉它们；
- `keep` 之内但调用方没给路径的，钉到临时空目录。只「不停用」是不够的：没有路径的适配器照样会回退到
  真实主目录（第一次修就是因为漏了这条，计数从 126 涨到 375，把 `~/.codex` 223 与 `~/.kimi-code` 148 扫了进来）；
- 遍历 `registry::catalog()` 而不是写死名单，以后新增来源不必再逐个补钉。

`cursor_内容版本号驱动增量扫描` 从 66s 降到 0.05s，反证它原先在扫真实数据。

## 5. 明确没做 / 没验证

- **pending 的路径未在本机验证**。这台机器 7 个内置来源都有真实数据，外部工具的路径无从核实，
  所以描述里写明了「未在本机验证」。要坐实它们，需要在装了对应工具的机器上看一眼。
- **字段映射不做自动猜测**。靠「试解析」让人来定；猜错映射不会静默成功（会返回明确错误），
  但我们也不会替你猜字段名。
- **`settings.json` 的字段映射没有图形化的「角色映射」多选**，只有 `bot=assistant, human=user`
  这样的文本输入。够用，但不好用。
- **试解析只采样前 3 个会话**。目录很大时看不到全貌——这是刻意的（试解析要快），
  但也就意味着「采样的 3 个对了」不代表整个目录都对。
- **桌面端鼠标点击的完整人工走查仍只覆盖了上面那条命令链路**。表单里改字段名、改布局、
  高级字段这些交互是 mock QA 覆盖的，没有在真机上一项项点过。
- **`id() -> &str` 是 trait 签名变更**，会影响任何第三方实现（本仓库内没有）。
  单独一个提交，便于回退。
