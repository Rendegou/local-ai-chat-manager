# 已知限制

本文档明确列出第一版（MVP）**不做**或**有取舍**的地方，避免误解。

## 产品范围

以下内容明确不在第一版范围内（规格要求，视为后续扩展）：

- LLM 长期记忆、Embedding、向量数据库、RAG、AI 摘要；
- MCP Server、云服务器、自建同步服务、用户系统、团队协作、在线聊天；
- 修改 Codex / Kimi Code 的原始会话文件（**永久只读**）；
- 把会话「恢复」到另一个 AI 工具里继续对话。

## 数据源

| 限制 | 说明 |
| --- | --- |
| 只支持 Codex / Kimi Code | 其他工具需要新增 Adapter（接口已抽象好） |
| Kimi 子 Agent 不进入主聊天 | `agents/agent-*/wire.jsonl` 只备份与登记，不参与主视图 |
| Codex 多 rollout 会话只取最新一份 | 同一 session 的多个 rollout 文件，以 mtime 最新者为内容来源，其余作为 `raw` 附件备份 |
| 标题可能缺失 | Codex 无 `thread_name` 且首条用户消息是系统注入内容时，标题显示为「无标题」 |
| 部分事件暂未识别 | 未知类型会计数并显示 `[未识别事件]`，会话标记为 `partial`；常见会话中此类占比 < 10%（本机实测 28/325） |

## 索引与搜索

| 限制 | 说明 |
| --- | --- |
| 高频词的排序成本 | 相关度排序需要为全部命中项打分。真实数据实测 2–11 ms；合成 100 万条消息 + 20 万命中（占 20%）的极端情况约 288 ms。若某关键词命中率极高，搜索会变慢（换取精确排序与高亮） |
| 单条消息文本上限 256KB | 超长工具输出在索引中截断（原始文件与 `raw/` 快照完整保留） |
| 未识别事件的 raw 上限 2KB | 只在索引里保存片段，完整数据以原始文件为准 |
| FTS5 分词为 unicode61 | 不做中文分词；中文按连续字符串匹配（子串命中依赖前缀/整词），`LIKE` 级模糊匹配不支持 |
| 索引可重建 | 索引是缓存，删除 `index.db` 后重新扫描即可恢复（不会影响原始文件与同步仓库） |
| 升级后建议重建索引 | 适配器规则变化（例如新增事件映射）需要重新解析才会作用到已有会话 |

## 同步

| 限制 | 说明 |
| --- | --- |
| 冲突不自动合并 | 检测到冲突只报告并提供「中止 Rebase / 重试 / 打开仓库」 |
| 依赖系统 git | 不内置 libgit2；凭据、SSH、代理等由用户本机 git 配置决定 |
| 归档不支持增量 | 归档是整会话打包；恢复后需要重新扫描（会自动进行） |
| 归档体积 | 使用 zstd level 3（速度优先）；不对已归档文件做二次压缩优化 |

## 平台

| 限制 | 说明 |
| --- | --- |
| Windows 构建链 | 官方推荐 MSVC；本机用 MinGW-w64（GNU 工具链）**已验证可编译、可打包**：NSIS 与 MSI 安装包均成功产出（见 README「验证结果」）。正式发布仍建议用 MSVC 工具链，以避开 GNU 链接器在 DLL 导出序号上的限制 |
| 未验证平台 | macOS / Linux 的代码路径已按平台条件编译写好，但**未在对应系统上编译运行过**（本仓库只在 Windows 上验证） |
| 无 Everything 集成 | Windows 下不依赖 Everything（它偏文件名搜索，且不跨平台） |
| 未做代码签名 | 自行构建的安装包可能触发系统安全提示 |

## 性能边界（实测数据）

| 场景 | 实测 |
| --- | --- |
| 325 个真实会话（77,263 条消息）首次全量解析 | 26.4 s（release） |
| 同数据集二次扫描（无变化） | 91 ms，解析 0 个 |
| 100 MB 单个 JSONL 会话（181,668 条消息） | 7.5 s（13.4 MB/s），**峰值内存 31 MB** |
| 100 万条消息索引（合成） | 写入约 43 s（≈2.3 万条/秒），索引约 249 MB |
| 100 万条消息搜索（单关键词命中 20%） | p50 288 ms / p95 305 ms |
| 真实数据搜索（325 会话 / 7.7 万消息） | 2–11 ms |
| 索引体积 | 约等于正文文本量的 1.7 倍（含 FTS 索引；external content 不重复存正文） |

> 具体数值随磁盘与数据分布变化，可用 `aichat-cli bench` / `bench-session` 在本机复测。
