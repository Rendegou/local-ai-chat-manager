## Design Specificity Verdict

**LLM assessment:** 四个一级页面和会话三栏结构符合产品任务，但现有视觉仍是可互换的深色开发者工具。`src/index.css` 只有中性灰表面与单一蓝色强调色；`src/components/ui.tsx` 的按钮、徽标、标题栏和字段高度依赖相同的圆角、边框和 10.5–12px 小字。Local-first、只读、来源、设备和同步可信度尚未转化为产品自己的视觉语言。

**Deterministic scan:** CLI detector 返回 1 条 `side-tab` warning，位置为 `src/features/conversations/ConversationViewer.tsx:190` 的 `border-l-2`。该样式与消息角色映射及背景色共同表达 user / assistant / tool / system，属于有语义的角色标记，因此判断为 false positive。自动检测没有发现其他规则问题，但它不会覆盖字号层级、认知负荷、响应式和任务连续性问题。

**Visual evidence:** `docs/images/demo-conversations.png` 显示三栏结构清楚，但大量低对比度小字、1px 分割线和近似表面让界面呈现为一个连续的黑色数据表格。浏览器页因本地访问被阻止而未完成可变脚本注入，没有可靠的用户可见 overlay。

## Overall Impression

这是一个工程结构优于视觉表达的产品。最好的机会不是换主题色，而是保留高效三栏工作流，重建表面、排版、状态与阅读组件，让产品从“调试面板”变成“可信的本地会话档案工作台”。

## What's Working

1. `ConversationsPage` 的左侧上下文、中间会话列表、右侧正文是正确的桌面工作流。
2. `SessionList` 与 `ConversationViewer` 已经具备虚拟滚动、分页加载和长内容处理，支持真实规模。
3. `SyncPage` 明确表达“不自动合并、不丢弃任何一边”，冲突文件、重试、打开仓库和中止 Rebase 的恢复路径较完整。

## Priority Issues

### [P1] 搜索结果没有定位到命中消息

- **Why it matters:** 长会话中，搜索只能定位到会话，不能完成“找到那条信息”的任务。
- **Evidence:** `SearchPage.tsx:162-169` 只切换页面并选中会话；`ConversationViewer.tsx:37-42` 始终从 offset 0 加载。
- **Fix:** 传递 message id / sequence，加载命中附近消息，滚动并高亮；保留搜索词、筛选与返回结果入口。
- **Suggested command:** `$impeccable clarify`

### [P1] 搜索过滤区一次暴露 8 个以上同权重决策点

- **Why it matters:** 用户难以判断先输入关键词还是先配置筛选，搜不到时也不容易诊断原因。
- **Evidence:** `SearchPage.tsx:88-145` 同时展示关键词、来源、项目、设备、起止日期和仅正文，排序位于另一处标题栏。
- **Fix:** 首层保留关键词、搜索、排序与 active chips；其余进入高级筛选；增加可见 label、日期校验与一键清除。
- **Suggested command:** `$impeccable distill`

### [P1] 窄窗口直接失去来源与项目筛选

- **Why it matters:** 调整窗口后核心 IA 不再完整。
- **Evidence:** `ConversationsPage.tsx:26-35` 在 `lg` 以下隐藏左栏，固定 340px 会话列表且无替代入口。
- **Fix:** 左栏改为可折叠抽屉；再窄时使用列表到详情的两级视图；工具栏持续显示筛选入口和摘要。
- **Suggested command:** `$impeccable adapt`

### [P1] 小字号、低对比度和弱焦点状态降低可读性与可访问性

- **Why it matters:** 键盘、低视力和高缩放用户难以识别当前页、当前会话与焦点；普通用户长时间阅读也容易疲劳。
- **Evidence:** `index.css` 的 13px 基础字号配合大量 `ink-faint`；`ui.tsx` 输入和 Select 使用 `outline-none` 且仅改变边框；导航和会话选择缺少 `aria-current` / `aria-selected`。
- **Fix:** 建立 16/14/12/11px 受控层级，提高 metadata 对比度，统一 `focus-visible` ring，补全 label、ARIA 与 reduced-motion。
- **Suggested command:** `$impeccable typeset`

### [P2] 同步、设置和危险操作缺乏阶段化层级

- **Why it matters:** 用户要在技术信息堆栈中寻找下一步，重建索引与同步风险也不够突出。
- **Evidence:** `SyncPage.tsx` 将仓库、变更、文件、步骤、归档、数据源和日志放在一条长页；`SettingsPage.tsx` 将增量扫描与重建索引并排。
- **Fix:** 重排为状态、推荐动作、预览、结果、高级诊断；将重建索引移入 Danger Zone，并增加确认和未保存保护。
- **Suggested command:** `$impeccable layout`

### [P2] 阅读器中执行噪声与正文竞争

- **Why it matters:** 工具消息默认全部展示，长输出形成内外双重滚动，破坏阅读连续性。
- **Evidence:** `ConversationViewer.tsx:26,74-78,119-125,203-207`。
- **Fix:** 视觉上将工具内容改为 console-like block，正文成为阅读主轴；默认折叠是否改变应作为独立产品决策。
- **Suggested command:** `$impeccable distill`

## Persona Red Flags

### Alex — Power User

- 从搜索结果进入会话后仍需从头寻找命中内容。
- 没有全局搜索、上下移动会话等快捷键。
- 页面切换后搜索上下文丢失，没有最近查询、保存筛选或快速定位。

### Sam — Accessibility-dependent User

- Field、日期输入和部分选择控件缺少可靠的语义 label。
- 当前页、当前会话、扫描进度和错误没有完整 ARIA 状态。
- `outline-none`、小字号和低对比度 metadata 让键盘和低视力使用困难。

### Jordan — First-timer

- 首屏没有单一、明确的“扫描并开始”路径。
- FTS5、Rebase、machine id、zstd 等术语缺少应用内解释。
- 数据源未找到只显示状态徽标，解决动作隐藏在设置页。

## Minor Observations

- README 示例图与当前 `App.tsx` 顶部操作已经漂移，重构完成后应重拍。
- 关键说明不能只依赖 hover `title`。
- 搜索日期没有显式 label，也没有起止关系校验。
- `includeArchived: false` 没有在搜索界面中解释。
- 设置页和 App 全局错误条可能重复显示同一错误。
- `Spinner` 没有 reduced-motion 处理。
- 长路径和机器标识经常被截断，但缺少复制或展开入口。

## Questions to Consider

- 用户最应记住的是“会话浏览器”，还是“可信的本地 Git 历史保险库”？
- 同步前是否应该清楚预览目标仓库和待上传内容？
- 阅读器默认服务于“阅读回答”，还是“审计完整执行轨迹”？
- 搜索的成功标准是否应该是“从关键词直接到命中消息”？
- 在 900px 宽窗口中，核心筛选还能否完整使用？

## Direction Decision

选择“保留结构的视觉重构”：保留四页、三栏关系、数据模型和工程能力；重建 design tokens、排版、焦点、状态、会话行、消息块、搜索分层、同步层级与响应式表达。视觉方向采用 Quiet Archive Workbench，以本地、只读、来源、设备和同步可信度形成产品辨识度。
